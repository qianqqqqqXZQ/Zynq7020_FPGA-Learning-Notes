# Zynq-7020 FPGA Learning Labs

Small, self-contained FPGA experiments for a Zynq-7020 board. The repository follows a simple Vivado layout so that each lab can be opened, simulated, and extended independently.

[中文说明](README.zh-CN.md)

## What is included

The labs move from basic combinational and sequential logic to clocking, memory IP, asynchronous FIFOs, and board-level interaction.

| Area | Labs |
| --- | --- |
| LED and timing | `led`, `flow_led`, `breath_led`, `key_led`, `touch_led` |
| User interaction | `top_key_beep`, `top_two_key_beep`, `touch_flow_led` |
| Clocking | `ip_clk_wiz` |
| Memory and storage | `ip_1port_ram`, `ip_2port_ram` |
| Clock-domain crossing | `ip_fifo` |
| Extended practice | `Homework/syn_flow_led`, `Homework/top_two_breath_led` |

Each completed lab normally contains:

```text
<lab>/
├── rtl/                 Verilog design sources
├── sim/tb/              simulation testbench (when applicable)
└── prj/                 Vivado project, XDC constraints, and IP metadata
```

## Toolchain

- Vivado 2025.2.1 (the projects target the Xilinx Zynq-7000 family)
- XSim for the supplied behavioral testbenches
- A Zynq-7020 development board using the pin assignments in each lab's XDC file

The project files contain board-specific pins and generated-IP references. If you use another board, replace the XDC pin assignments before synthesis or implementation.

## Open a lab

1. Start Vivado and open a lab's `.xpr` file under `Projects/<lab>/prj/` or `Homework/<lab>/prj/`.
2. Review the top module and the matching XDC file.
3. Run **Run Simulation** for a behavioral check, then synthesize or implement when the board is connected.

Vivado regenerates cache, IP output products, simulation databases, and implementation runs locally. Those files are intentionally ignored by Git. The checked-in `.xci` files are the portable IP configuration; regenerate output products after cloning.

## Simulation from the command line

For a project with a generated XSim script, run the commands from its generated `prj/<name>.sim/sim_1/behav/xsim/` directory:

```powershell
xvlog --relax -prj <testbench>_vlog.prj
xelab --relax -debug typical xil_defaultlib.<testbench> xil_defaultlib.glbl
xsim <snapshot> -tclbatch <testbench>.tcl
```

The exact snapshot name is generated by Vivado and may change when IP output products are regenerated. The RTL and testbench sources remain the stable inputs.

## Repository hygiene

Only source, constraints, Vivado project definitions, IP configuration, testbenches, and documentation belong in commits. Build products, bitstreams, checkpoints, waveforms, logs, and simulator work directories are excluded by [`.gitignore`](.gitignore).

## Learning notes

The project is intentionally incremental. Start with `led` and `flow_led`, then compare the counter-based timing in `breath_led` with the input synchronization and debounce logic in the key/touch labs. The RAM and FIFO labs are useful follow-ons for synchronous memory, generated IP, and clock-domain crossing.
